# Cluely upload bundle

A curated set of 13 markdown files for upload to Cluely workspace. Designed to be the **primary reference visible during the live screen-share interview** when the harness CLI is in another window.

## Why these files exist

Cluely is your teleprompter. The harness CLI (`pnpm harness ask "..."`) is your queryable corpus. These docs are the **scrollable, searchable backup** for when:

- You're not in `claude` and can't call MCP tools
- The harness output is too verbose and you want a quick reminder
- The interviewer asks something soft (methodology, anti-patterns)
- You want to glance at a "what to say first" prompt mid-flow

## Upload order (matters because docs cross-reference each other)

1. **[00-context.md](00-context.md)** — who you are, the role, eval criteria. Cluely should show this at start-of-screen-share.
2. **[01-cheatsheet.md](01-cheatsheet.md)** — single-page reference: exit codes, signal map, harness commands, common error → fm-id.
3. **[02-symptom-to-fm.md](02-symptom-to-fm.md)** — "user says X → call `harness playbook Y`". The fastest path from symptom to runbook.
4. **[03-top-failure-modes.md](03-top-failure-modes.md)** — the 50 highest-confidence failure modes across all 7 domains, with diagnostic + fix steps inline.
5. **[04-diagnostic-commands.md](04-diagnostic-commands.md)** — the commands you'll actually type, grouped by category (containers, processes, network, disk, certs).
6. **[05-methodology.md](05-methodology.md)** — USE / RED / 4 Golden Signals condensed; postmortem framing rules.
7. **[06-talk-tracks.md](06-talk-tracks.md)** — literal scripts to read aloud at key moments (opener, mid-diagnosis, when stuck, when finishing).
8. **[07-anti-patterns.md](07-anti-patterns.md)** — what NOT to do; common interview tripwires.
9. **[08-recovery.md](08-recovery.md)** — if the harness crashes / DB is corrupt / install broke mid-interview, the manual fallback paths.
10. **[09-triage-and-customer-fix.md](09-triage-and-customer-fix.md)** — decision tree for "is this our bug or theirs?" + customer-side fix workflows.
11. **[10-mcp-full-guide.md](10-mcp-full-guide.md)** — comprehensive MCP usage guide: all 8 tools, CLI fallbacks, query script, decision tree.
12. **[RCA-EXAMPLE-MULTI-SYMPTOM-GATEWAY.md](RCA-EXAMPLE-MULTI-SYMPTOM-GATEWAY.md)** — worked RCA example: multi-symptom gateway failure.
13. **[SESSION-PROMPTS.md](SESSION-PROMPTS.md)** — session prompt templates for corpus build phases.

## How they cross-link

```
00-context ──┬─ everything (background)
             │
01-cheatsheet ─── 02 / 03 / 04 (drill-downs from quick-ref)
             │
02-symptom-to-fm ─── 03 (each fm-id resolves to a top-fm entry here)
             │
03-top-failure-modes ─── 04 (fm diag steps reference command groups)
                     ─── 05 (fm fixes invoke methodology framings)
             │
04-diagnostic-commands ─── 03 (commands grouped by what fms use them)
             │
05-methodology ─── 06 (talk tracks invoke USE/RED frames)
             │
06-talk-tracks ─── 07 (anti-patterns reinforce talk-track rules)
             │
07-anti-patterns ─── 08 (recovery includes "what to say if the harness crashes")
             │
08-recovery ─── all (last resort if everything else fails)
```

## Constraints I designed for

- **Self-contained**: no network calls, no harness dependency. Every file is plain MD readable in any viewer.
- **Compact**: each file ≤ ~5 KB (most ≤ 3 KB) so they render fast in Cluely's panel and you can scan in <30 sec.
- **Action-oriented**: bullet points, tables, code blocks. No lectures.
- **Auto-derivable from corpus**: 02 + 03 + 04 are generated by the script at `packages/harness/scripts/build-cluely.ts` so they stay in sync as the corpus evolves. Re-run with `pnpm cluely`.

## How to upload to Cluely

In the Cluely workspace UI: drag-drop all 13 .md files into your workspace. Cluely indexes them; during the interview the panel can search across all uploaded files. Set 00-context.md as "open by default".

## Updating

If the corpus changes (new fms, new commands), regenerate the auto-built files:

```bash
pnpm cluely     # rebuilds 02, 03, 04 from current DB state
```

The hand-curated files (00, 01, 05, 06, 07, 08, 09, 10) don't need regeneration unless you want to add new content.
